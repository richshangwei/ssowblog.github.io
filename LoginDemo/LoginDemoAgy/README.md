# 振興醫院 — 多系統共用登入網站 10 款前端原型

本專案由**資深資訊室主任視角**出發，整合產品規劃、資訊服務管理 (ITSM)、UI/UX 設計與前端工程，針對醫院與大型組織的多業務系統共用入口進行完整架構設計。

專案全面採用 **Bootstrap 5.3.3 + jQuery 3.7.1 + Bootstrap Icons 1.11.3**，本機自帶離線相依套件，**不需安裝 Node 套件或啟動伺服器，直接用瀏覽器開啟任一 HTML 即可完整操作**。

## 🎯 資訊室主任核心思考：解答使用者的 5 大關鍵疑問

每一款設計原型皆圍繞「幫助同仁順利完成登入、理解狀態、取得協助」三個核心目的，於登入前清楚解答：

1. **這是哪個組織的登入入口？**  
   組織名稱（振興醫療財團法人振興醫院）、院徽 Logo、明確標示為「全院資訊服務共用登入入口」，避免同仁誤以為是單一系統私有門戶。
2. **應使用什麼帳號登入？**  
   清楚揭露身分規則：全院專職同仁使用「員工編號（E開頭）」、廠商使用核發之「V開頭帳號」，並提供首次開通與密碼長度（12碼）規範。
3. **目前準備進入哪個系統，或登入後可以做什麼？**  
   * **情境 A（直接開啟共用入口）：** 登入成功後跳出 Modal 展示同仁依個人權限配置之業務系統清單（HIS、NIS、HRM 等）。  
   * **情境 B（由特定業務系統導向）：** 登入前顯示「目標系統提示」，成功後示範導回該系統；若無權限，提供清楚原因說明與「權限申請作業指引」。
4. **是否有影響目前操作的維護或服務異常？**  
   * 提供各系統運作狀態（正常、部分異常、維護中、狀態未確認）與最後探測時間。  
   * **重大異常於登入送出前即可看見**，清楚列明：影響系統、發生時間、處理進度、**已確認的替代作法（例如：衛材維護期間請依紙本急用三聯單領料）**與最後更新時間。
5. **登入失敗或需要協助時，可以採取什麼行動？**  
   * **免登入支援通道**：保留不依賴登入的服務台電話（分機 5888）、夜間值班專線（分機 5800 / 0912-345-678）。  
   * **免登入問題線上回報**：自動帶入端點診斷參數與錯誤代碼，**嚴禁要求使用者提交密碼或病患敏感個資**。  
   * **防探測安全錯誤訊息**：驗證失敗時統一提示「帳號或密碼驗證未通過」，不透露帳號是否存在，防止惡意探測。

## 🎛️ 每款頁面均內建「展示情境切換條」

開啟任一款式頁面，頂部皆有一條與正式畫面清楚區隔的**展示情境切換列**，評選主管可一鍵測試：

1. **情境切換**：
   * `1. 正常運作`：服務全數正常。
   * `2. 重大維護/異常`：即時彈出紅色重大通報，展示受影響系統與替代領料三聯單作法。
   * `3. 驗證失敗`：送出登入時模擬防探測之安全錯誤反饋與求助指引。
   * `4. 服務逾時`：模擬伺服器連線逾時與離線應變手冊通報。
2. **入口情境切換**：
   * `A. 直接開啟共用入口`：登入成功後展示「個人已授權系統選單 Modal」。
   * `B. 由特定業務系統導向`：登入前提示「即將前往：人事差勤系統」，登入成功後展示「導回目標系統」或「無使用權限說明與申請」。
3. **權限切換**：可切換「有權限」與「無權限」以檢視不同回饋。

## 🏆 資訊室主任選型建議（最推薦前三款）

1. **首選推薦 No.1：Style 01 (雙欄標準管理型)**  
   * **理由**：資訊架構最平衡，左右分工明確，符合一般同仁心智模型。  
   * **微調建議**：行動裝置檢視時，確保重大異常告警優先於表單上方顯示。
2. **推薦 No.2：Style 07 (側邊工作站導航型)**  
   * **理由**：最適合醫院護理站、藥劑部與檢查室常駐螢幕，側邊常駐狀態與電話能實質減少打電話詢問「系統有沒有壞」的客服負載。  
   * **微調建議**：在 1024x768 舊款病歷推車上，需支援側邊欄自動折疊。
3. **推薦 No.3：Style 10 (全齡友善觸控型)**  
   * **理由**：60px 超大觸控目標與嚴格的防窺提示，在急診病房輪班情境下錯誤率最低。  
   * **微調建議**：可依登入來源 IP 網段自動載入此模式。

## ⚙️ 系統落地整合待確認事項 (Checklist)

| 整合領域 | 影響落地的關鍵問題 | 現狀與建議方案 |
|---|---|---|
| **帳號來源** | Windows AD / LDAP 目錄同步機制 | 原型採前端模擬。正式環境需對接 AD，確認兼職人員帳號生命週期與鎖定策略。 |
| **驗證協定** | SAML 2.0 / OIDC 單一簽入 (SSO) | 「多系統共用」不等於 SSO。需盤點舊版 HIS/NIS 是否支援標準 SSO 權杖。 |
| **系統導向** | 目標系統 ReturnUrl 與防開放重定向安全 | 需建立業務系統白名單機制，防止釣魚轉導漏洞。 |
| **權限資料** | 登入後依權限動態派發系統清單之 RBAC API | 需確認各業務系統是否有統一的授權查詢中台或中繼快取。 |
| **服務狀態** | 即時健康探測 (Healthcheck API) 來源 | 需串接資訊室 APM。若探測服務離線，前端應標示「狀態確認中」，嚴禁冒稱正常。 |
