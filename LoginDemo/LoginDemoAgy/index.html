資訊室主任選型建議：最適合正式入口的前三款

首選推薦 No.1
Style 01: 雙欄標準管理型

推薦理由：資訊架構平衡度最高。符合醫院使用者「左眼看登入、右眼看公告」的習慣路徑。頁籤能容納豐富維護日誌，且不會造成首頁資訊過載。

落地調整建議：在手機響應式時，可預設將重大異常橫幅置於表單最上方，確保行動端同仁在送出前能看見。
推薦 No.2
Style 07: 側邊工作站導航型

推薦理由：最具醫院「工作站」專業格局。常駐的左側欄讓護理同仁隨時掌握服務台電話與各系統燈號，減少致電資訊室詢問「系統有沒有壞」的通話量。

落地調整建議：針對 1024x768 舊款病歷車螢幕，需設定左側欄在窄螢幕自動收合為漢堡選單。
推薦 No.3
Style 10: 全齡友善觸控型

推薦理由：在公用工作站、急診櫃檯與高齡主治醫師情境下表現最好。60px 觸控目標與防窺警告，實質杜絕誤按與帳號被偷看的稽核風險。

落地調整建議：可透過前端 UserAgent 或 IP 網段自動判斷，若是臨床診間特定 IP 網段則自動切換此大字模式。

系統落地整合待確認事項 (IT Implementation Checklist)

1. 帳號來源與目錄服務 (AD / LDAP)

共用入口需介接全院 Windows AD 或 OpenLDAP，目前原型為前端模擬。正式上線前需確認：帳號啟用狀態欄位、兼職醫師多重身分規則、以及帳號鎖定 (BadPwdCount) 的同步機制。

2. 驗證協定 (SAML 2.0 / OIDC)

「多系統共用登入」不等於已完成單一簽入 (SSO)。需確認各業務系統（HIS、NIS、HRM）是否支援標準 SAML 2.0 或 OAuth2/OIDC 權杖轉發，以實現一次登入後免密碼安全跳轉。

3. 目標系統導向與返回回跳機制 (ReturnUrl)

由特定系統導向共用入口時，URL 須帶入加密之 ReturnUrl 與 State Token；登入完成後透過後端重定向導回，並防止開放重定向 (Open Redirect) 資安漏洞。

4. 即時服務狀態與探測介接 (Health Check API)

服務狀態矩陣需對接資訊室 APM 或伺服器健康探測 API，每 5~10 分鐘更新。若探測服務暫時離線，前端應顯示「狀態確認中」，嚴禁無依據直接顯示「全數正常」。
