# 節慶主題與背景主視覺模式

十款共用入口使用同一個節慶模組。主題管理背景、文案及配色，版面模式管理資訊的展開方式；兩者可以分開設定。預設不啟用節日排程，保留原本十款設計。新春與中秋是外觀示範，未代表任何已確認的組織活動或節日日期。

## 使用與預覽

在每款頁面上方的「節慶展示」選擇節慶主題與版面模式。這些控制與正式登入畫面分開，僅供比較設計；總覽的「節慶模組」也能直接開啟兩組示範。

- **原版配置 `standard`：** 保留各款的資訊架構，可以套用節慶配色與背景。
- **背景主視覺 `immersive`：** 背景取得較大的視覺空間，一般資訊預設收合，點選後閱讀。
- **網址預覽：** 在任一款 `index.html` 後加入 `?theme=spring&layout=immersive`，或使用 `?theme=midautumn&layout=immersive`。如已使用目標系統參數，可寫成 `?target=hr&theme=spring&layout=immersive`。

背景模式仍須讓使用者立即知道組織、共用入口用途、如何登入、目標系統及免登入求助管道。服務狀態摘要保持可見；影響目前操作的維護／異常提示、輸入錯誤及登入結果不會因節慶而收起。一般公告、完整服務說明、FAQ 與延伸帳號說明才使用點選展開。

外觀切換沿用同一份登入表單及流程，移動並恢復原本的元素，不建立另一套登入欄位。節慶切換不應清除使用者正在輸入的內容，也不代表服務恢復正常、已有真實帳號驗證或完成 SSO。

## 維護位置

| 檔案／目錄 | 用途 |
| --- | --- |
| `portal-src/seasonal/config.js` | 共用主題資料、配色及日期排程 |
| `portal-src/seasonal/assets/` | 本機背景資源，包含桌機及手機版本 |
| `portal-src/seasonal/engine.js` | 主題選擇、排程與版面切換邏輯 |
| `portal-src/seasonal/seasonal.css` | 共用配色套用、背景模式與跨裝置配置 |
| `portal-src/SEASONAL-GUIDE.md` | 本說明來源 |

請修改來源，再於工作區根目錄執行：

```powershell
node LoginDemoCode/build.cjs
```

建置後，十個 `portal-*` 資料夾會各自取得節慶模組與資源，維持可獨立開啟、離線預覽的結構。不要只修改某一款的產出檔案，否則下次建置會覆寫修改。原先四款及先前十款單一系統登入設計仍是歷史參考，本模組套用於目前的十款共用入口。

## 新增一個節日

1. 將有權使用的背景圖放入來源的 `seasonal/assets/`。可使用本機 SVG、JPG、PNG 或 WebP，不必依賴外部圖床；手機版另提供裁切適合直向閱讀的背景。
2. 在 `window.PortalSeasonalConfig.themes` 複製一組現有主題，給予唯一代碼，例如 `anniversary`。
3. 替換名稱、短文案、圖片位置與色票。背景不承載必要操作說明；必要資訊仍用可讀取的 HTML 文字呈現。
4. 先以展示控制或網址預覽，確認十款與不同裝置，再設定正式啟用日期。
5. 執行建置，交付或部署產出的頁面及完整資源目錄。

主題欄位說明：

| 欄位 | 維護要點 |
| --- | --- |
| `name` | 控制選單顯示的主題名稱 |
| `headline`、`message` | 背景區短標題及說明，避免暗示服務承諾 |
| `background`、`mobileBackground` | 桌機、手機背景的本機相對路徑，使用 `seasonal/assets/` 開頭，英文、數字、連字號或底線檔名；不接受外部網址或向上目錄路徑 |
| `backgroundPosition`、`mobileBackgroundPosition` | 背景裁切焦點，例如 `center center`；不要讓重點圖像被登入區遮住 |
| `preferredLayout` | 此主題偏好的 `standard` 或 `immersive` 模式 |
| `palette.bg`、`palette.surface` | 頁面底色與內容面板底色 |
| `palette.ink`、`palette.muted` | 主要文字與輔助文字色；輔助文字仍須清楚可讀。所有色票使用六位十六進位色碼，例如 `#372B2A` |
| `palette.line`、`palette.soft` | 分隔線及次要區塊背景 |
| `palette.accent`、`palette.onAccent` | 主要操作的背景與文字，必須成對檢查對比 |
| `artInk`、`artMuted` | 背景主視覺區的文字色，需對照桌機與手機實際圖片檢查 |

不要把節慶品牌色套成服務狀態。正常、異常、維護與未確認仍由服務資料決定，並且搭配文字說明。

## 日期排程

設定包含 `timeZone: 'Asia/Taipei'`、`defaultTheme: 'default'`、`defaultLayout: 'standard'`、`scheduleEnabled: false` 及 `schedules: []`。排程啟用後，依設定時區的日曆日期選擇主題，起日與迄日都包含在內。沒有符合的有效排程時，回到預設主題及版面；未知主題不得變成任意外部圖片來源。

每筆排程使用以下欄位。以下是**欄位示意**，日期必須替換為已確認的實際年月日後才可啟用：

```javascript
{
  id: 'spring-approved-year',
  theme: 'spring',
  start: 'YYYY-MM-DD',
  end: 'YYYY-MM-DD',
  priority: 10,
  layout: 'immersive',
  enabled: false
}
```

`start`、`end` 使用 `YYYY-MM-DD` 格式；`end` 不得早於 `start`。多筆日期重疊時，以較大的 `priority` 優先，相同優先序再依 `id` 排序。每筆 `id` 應唯一。確認日期及圖片後，將該筆 `enabled` 及整體 `scheduleEnabled` 設為 `true`。

農曆節日不以固定國曆月日每年重複，也不由此模組自行換算。請逐年取得可靠日期，再填入已確認的起迄日。展示控制及網址選擇用於人工預覽，不應作為正式節日判斷的依據。

「排程預覽日期」只改變判定日期；要觀察排程，外觀選單須選「依設定日期自動套用」。手動選定的主題優先於排程；「回到日期自動套用」會清除手動主題、模式與模擬日期，不清除登入情境。未啟用排程時，選任何模擬日期仍顯示日常外觀。

頁面初次開啟、回到頁面及每分鐘的跨日檢查會重新判定日期。無有效規則、非法日期或未知主題時使用預設；時區設定錯誤會顯示原因並使用預設。規則變更需重新發布並重新載入頁面，這不是即時遠端設定服務。

目前由瀏覽器取得日期；正式環境如需防止用戶端時間不準，應由受信任的設定／伺服器時間來源決定啟用主題。主題設定的發布權限、審核及緊急停用方式也需納入維護流程。緊急停用可關閉 `scheduleEnabled`，並確認預設主題為 `default`。

## 每次換圖的檢查

- 桌機、平板、手機直向及橫向沒有水平溢出；登入與求助入口容易取得。
- 背景裁切不遮住文字；圖片未載入時，底色與面板仍讓登入清楚可用。
- 文字、按鈕與焦點的對比足夠；展開操作可用鍵盤及觸控，狀態不只靠顏色辨識。
- 切換主題、模式與收合區塊後，登入欄位仍只有一份，填寫內容與操作焦點合理保留。
- 維護、部分異常、狀態未確認、驗證失敗、網路失敗及逾時情境，都能在必要位置看到下一步。
- 直接入口與指定系統導向都能完成示範結果，無權限時仍有申請及求助入口。
- 測試起迄日、日期外、重疊規則及排程停用。節日改變不會改寫真實服務狀態，也不會收集、儲存或傳送密碼。

新背景與色票仍需逐次檢查，現有範例的驗證不代表未來任意素材都已符合無障礙要求。
