# 多系統共用登入入口 — 十款前端原型

開 `portal/index.html` 就是總覽入口：共同資訊架構、操作流程、十款可切換預覽、差異比較表、
設計評估、選型建議與待確認事項都在同一頁。

## 檔案結構

```
portal/
├─ index.html                 # 總覽（比較、預覽切換、選型建議、待確認事項）
├─ p01-focus.html             # 中央聚焦
├─ p02-split.html             # 左右分割
├─ p03-status-banner.html     # 狀態橫幅三欄
├─ p04-sidebar.html           # 側欄導覽
├─ p05-status-first.html      # 狀態看板優先
├─ p06-steps.html             # 三步驟引導
├─ p07-help-first.html        # 意圖導向
├─ p08-system-grid.html       # 系統目錄
├─ p09-document.html          # 文件式長頁
├─ p10-kiosk.html             # 共用工作站（大字觸控）
├─ assets/
│  ├─ portal-data.js          # ★ 示範資料：組織、系統、狀態、公告、FAQ、支援、假設、待確認
│  ├─ portal-core.js          # 區塊產生器（多種呈現變體）＋ 登入流程 ＋ 展示控制列
│  └─ portal-base.css         # 功能性基礎樣式（可讀性／無障礙／展示控制列）
└─ README.md
```

十款共用 `portal-data.js` 與 `portal-core.js`，功能完全一致；每個 HTML 只負責版面結構與視覺語言。
所有樣式、圖示、jQuery 與 Bootstrap 5 皆讀取本機檔案（`../assets/libs/`），不連外部服務，可在完全無外網的內網運作。
字型只使用系統內建字型。

## 資料揭露原則

- 未提供的組織資料一律使用替換欄位：`[組織名稱]`、`[資訊室分機]`、`[服務時段]`、`[外線電話]` 等。
- 公告、系統清單與服務狀態皆為**示範資料**，畫面上都有標示。
- 未取得狀態資料時顯示「**狀態未確認**」，不顯示「全部正常」。
- 沒有可靠依據時，不承諾恢復時間、處理時限或服務可用率。
- 「共用登入畫面」不等於已完成 SSO；SSO／AD／LDAP／MFA／帳號同步全部列為待確認整合條件。

## 展示控制列

每一款底部都有一條紫色斜紋的「展示控制」列，與正式畫面明確區隔，可切換：

| 控制項 | 可選值 |
|---|---|
| 入口情境 | 直接開啟共用入口／由特定系統導向 |
| 目標系統 | 可公開的五個示範系統 |
| 服務狀態 | 服務正常／部分異常／維護中／狀態未確認 |
| 登入結果 | 成功（有權限）／成功（無權限）／帳密失敗／登入服務無法使用／工作階段逾時 |

狀態也會寫進網址參數（`?entry=&sys=&service=&result=`），方便把特定情境的連結貼給別人看。

## 共同資訊架構（八區）

| 功能區域 | 內容 |
|---|---|
| 組織識別 | 組織名稱、Logo 預留位置、入口名稱與用途說明 |
| 登入操作 | 帳號、密碼、顯示／隱藏密碼、登入按鈕、帳號格式提示 |
| 登入情境 | 目標系統提示；直接進入時說明登入後的下一步 |
| 帳號協助 | 忘記密碼、帳號申請、權限申請、首次使用說明（皆不需登入） |
| 服務狀態 | 四種狀態＋更新時間，皆有文字說明，不只用顏色 |
| 重要公告 | 首頁只放重要的，其餘「查看全部」 |
| 支援服務 | 常見問題、問題回報、聯絡方式與服務時段 |
| 基本資訊 | 維護單位、隱私與使用說明 |

公告欄位：重要程度、適用範圍、影響對象、時間、處理狀態、您現在可以、替代方式、最後更新、
下次更新、發布單位、有效期限、可見範圍。

## 以資訊室主任角度主動補充的項目

| 補充項目 | 加入原因 |
|---|---|
| 送出前的重大影響橫幅 | 避免「登進去才知道在維護」，受影響者在按登入前就看到 |
| 目標系統確認區 | 直接回應「不知道現在開的是哪個系統」 |
| 「狀態未確認」這個狀態 | 沒資料就顯示正常會侵蝕信任，必須與「已確認正常」分開 |
| 「記住帳號」與「保持登入」分開 | 共用工作站是常態，兩者風險不同，皆預設不勾選 |
| 共用電腦提醒 | 值班與交接時段常見帳號混用 |
| 「登不進去」常見原因分流 | 使用者分不清密碼錯／沒權限／維護中，先分流可減少無效通報 |
| 問題回報帶入脈絡 | 自動帶入目標系統、時間與錯誤代碼；明文禁止填寫密碼與業務資料 |
| 可公開的系統清單 | 新進同仁需要知道入口裡有什麼；敏感系統留在登入後 |
| 「成功但無權限」獨立結果 | 最易被誤判為帳號問題，獨立呈現並接到權限申請 |
| 展示控制列 | 不改程式即可切換情境比較十款，並與正式畫面明確區隔 |

刻意不做：天氣、時鐘、訪客計數、裝飾動畫、一般公告強制彈窗、登入前個人化內容、
以及在錯誤訊息中透露帳號是否存在。

## 十款差異

| 款式 | 版面結構 | 登入區位置 | 公告呈現 | 導覽方式 | 視覺語言 |
|---|---|---|---|---|---|
| P01 中央聚焦 | 單欄置中 | 第一屏正中央 | 精簡單行清單（2 則） | 無導覽 | 白底細線、資訊量最低 |
| P02 左右分割 | 左資訊／右操作各半 | 固定右半邊 | 完整清單 | 左欄分段 | 深藍 vs 白，明暗分工 |
| P03 狀態橫幅三欄 | 頂部狀態橫幅＋三欄 | 正中央欄 | 卡片格狀 | 三欄分工 | 淺灰底白卡片 |
| P04 側欄導覽 | 左導覽＋右內容區 | 預設分頁 | 表格 | 側欄分頁 | 深色側欄，行政系統感 |
| P05 狀態看板優先 | 主區看板＋右固定欄 | 右側 sticky | 手風琴 | 右欄常駐 | 看板式大卡片 |
| P06 三步驟引導 | 精靈式三步 | 第二步 | 第一步精簡清單 | 步驟列 | 流程導向、大按鈕 |
| P07 意圖導向 | 三個意圖大按鈕 | 「我要登入」內 | 意圖內清單 | 意圖分頁 | 問句式、服務台窗口感 |
| P08 系統目錄 | 系統卡片牆＋右登入 | 右上 sticky | 橫幅＋側欄清單 | 以系統為導覽單位 | 目錄／型錄感 |
| P09 文件式長頁 | 目錄＋文章＋右登入卡 | 右側 sticky | 手風琴、欄位完整 | 目錄錨點 | 襯線標題、白紙感 |
| P10 共用工作站 | 單欄三段 | 第一屏滿版 | 只顯示影響操作的 | 無導覽 | 18px、高對比、觸控 ≥ 56px |

## 選型建議（前三）

1. **P03 狀態橫幅三欄** — 三個核心問題各佔一欄，狀態橫幅最不可能被忽略，登入仍是視覺重心。
   需調整：公告超過 6 則時左欄過長；13 吋筆電三欄偏擠，中欄建議固定 420px。
2. **P01 中央聚焦** — 最不容易出錯，手機幾乎不用重排，適合使用者組成複雜的組織。
   需調整：狀態膠囊列較不醒目；公告只放 2 則，需要嚴謹的重要程度規則。
3. **P10 共用工作站** — 建議與前兩名**並存**，部署在護理站、櫃台、值班室。
   需調整：需與資安確認是否停用「保持登入」；建議加入閒置自動清空欄位。

## 待確認事項（影響落地）

帳號來源、驗證方式（是否 SSO／MFA）、密碼政策與重設驗證、鎖定與稽核規則、系統導向與白名單、
權限資料來源與更新頻率、公告發布與分眾、服務狀態資料來源、問題回報要進哪個系統、
隱私與無障礙法遵、內網環境限制、品牌識別資料。完整清單見 `index.html` 第十節，
資料在 `assets/portal-data.js` 的 `openQuestions`。

## 注意事項

- 本原型不做任何真實驗證，帳號密碼不會送出至任何伺服器，也不會儲存。
- 正式上線時必須走 HTTPS、保留登入稽核紀錄，並依鎖定政策限制連續失敗次數。
- 錯誤訊息刻意不透露帳號是否存在，導入時請維持同樣原則。
